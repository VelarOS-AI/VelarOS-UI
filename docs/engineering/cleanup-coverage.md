# UI 语义与职责审查

基线：UI 1.1.0（`131bab8178913bed8392c61c473693aa910e941f`）。本轮内部清理保持公开 props、exports 和版本，不引入产品状态和传输逻辑。样式变更只修已确认的布局或交互缺陷。

## 输入交互准入

| 范围 | 发现与处理 | 保留行为 |
| --- | --- | --- |
| `ChatInput` 文件拖放 | 嵌套计数与遮罩布尔值分别维护；准入撤销时 drop 提前返回会留下旧状态。改用单一拖拽计数派生遮罩，撤销准入清空计数，drop 先结束拖态再决定接收。 | 嵌套拖入/离开、正常附件接收、禁用与缺失附件处理器时拒绝附件。 |
| `useComposerMentionMenu` | 菜单在普通编辑逻辑之前消费 Shift+Enter 和修饰方向键。只处理没有修饰键且不处于 IME 组合期的菜单按键。 | 普通方向键导航、Enter 选择引用、输入法组合与原生编辑按键。 |

真实路径：Workbench 提供引用菜单；执行等待确认会禁用输入，可能发生在拖拽过程中。其他产品的公开接入不变。组合回归 `test/composerInteractionLifecycle.test.mjs` 在隐藏 Chromium 窗口挂载真实输入框，覆盖编辑快捷键、普通引用选择、准入撤销、处理器移除与后续嵌套拖放。验证结果与提交标识由本文件所在批次的 Git 历史及交付回执记录。

验证：类型检查、改动文件 lint、Hook 依赖与模块归属均通过。四个相关测试文件首次运行 30 项通过，1 项失败；失败项仍从 CSS 聚合入口查找已拆分规则。已单独校准为检查入口导入与所属样式模块，定向复查通过，其余已通过结果保留。新增键盘回归证明菜单不消费修饰键，不等同于验证浏览器的原生编辑默认动作。未运行整仓回归或生产构建。

## 阅读位置与消息窗口

触发条件：Desktop 开启 `rememberView`，用户进入末尾 60 条之外的历史窗口，再切换会话或卸载后打开。滚动快照仍保存旧消息身份和视口偏移，转录窗口却在被动 effect 中无条件回到末尾，旧像素因此可能落到另一条消息。

`useScrollToBottom` 继续独占快照写入；它按实际恢复键与重置键创建 ref，私有读取器只提供当前范围、持续跟随状态和已有快照。`useChatTranscriptWindow` 在子树挂载前选择包含恢复锚点的对话节，再由原滚动钩子恢复偏移，不增加第二份会话窗口缓存。不为锚点恢复新增历史加载请求，消息到达后按身份选段；原有哨兵、轮次边界、窗口预算和活动消息保留规则继续沿用。

组合回归还确认了同一职责冲突：读者在早期窗口发送新一轮消息时，滚动钩子重置贴底，但窗口仍停在旧段，新增消息没有挂载。现在同范围的重置键变化与开启持续跟随都会先选择真实末尾，显式回底继续走原导航入口。窗口位置与所属范围同次更新，拒绝旧范围已经排队的状态更新；容器监听也核验当前 ref，避免清理前的迟到事件改写新窗口。

`test/chatScrollLifecycle.test.ts` 的真实 Chromium 回归将滚动钩子放在父组件、窗口钩子放在子组件，覆盖独立恢复键、长会话 A→B→A、历史前插与高度变化、整段卸载及延迟历史、阅读期间内容追加、显式回底、新消息重置和持续跟随。测试构建使用源码别名，进程关闭后才读取完整回执。

验证：最终源码的类型检查、改动文件 lint、Hook 依赖与模块归属均通过，扩展后的 Chromium 组合回归通过。另两份滚动行为测试的 29 项通过结果保留，输入批次的已通过检查不重跑。未运行整仓回归、生产构建或三产品实机验收。

## 日期选择器的月份所有权

`CalendarDatePicker` 与 `CalendarDateRangePicker` 在 UI 包装器内传入固定月份，却没有维护月份变更，导致用户无法导航。Desktop 的 `TokenUsagePage` 只传日期范围，错误接线属于 UI。移除包装器多余的 `monthValue`，保留底层真正受控的 `Calendar` / `CalendarRange` 合同；`defaultMonth` 仍以已选日期或范围起点初始化。

真实 Chromium 回归覆盖旧日期初始月份、切月选日、跨月范围选择、关闭重开定位、半成品不提交及 min/max 导航。集中类型、改动 lint、Hook 依赖和模块归属检查通过；依赖以 `aria-disabled` 表达导航边界，夹具据此校准并验证点击不会越界。多个浏览器回归共用隔离窗口与临时资源回收助手，不重跑输入或滚动批次。

## 拖拽生命周期

`usePointerResize` 由 Desktop 的分栏直接消费，原实现接纳右键和非主指针，也没有在失焦或卸载时释放全局监听及光标。现在单个活动清理器持有所属指针，重复开始先释放旧操作，结束、取消、失焦和卸载统一恢复原光标及文本选择。

集中类型与改动 lint、Hook 依赖、模块归属均通过；真实 Chromium 回归覆盖按钮准入、异指针不移动或结束、正常位移、取消、重复开始、失焦、卸载与重挂，确认没有遗留回调或双监听。

## 共享布局与折叠交互

`SessionStickyDock` 的裁剪动画保留正文挂载，却让隐藏的目标动作仍能获得焦点。正文现在随折叠设置 `inert`，自动收起前将正文焦点交回触发按钮；按钮复用已有 `barLabel` 命名，不新增文案或公共参数。用户输入与正文节点在开合后仍保留。

`DescriptionList columns={2}` 的双列规则被后面的无条件单列规则覆盖，实际影响 People 详情。将堆叠限制在原意对应的窄屏范围，保留单列与 `spanFull` 行。真实 Chromium 验证宽/窄视口的计算列数、全宽行、折叠正文的焦点隔离、自动收起归还焦点与内容不重挂；类型、改动 lint、Hook 依赖和模块归属结果均通过。

## 接入边界与保留理由

| 范围 | 已确认情况 | 下一步 |
